# 消息状态、时间与有效变更

## 状态标签

通知标题使用保守的规则分类，保留原文与来源链接供读者复核：

| 标签 | 含义 |
| --- | --- |
| 重置预告 | 来源宣布将重置，或今天有重置安排；未确认完成 |
| 来源称已完成 | 来源正文明确声称已重置、额度已生效等；没有独立核验个人账号 |
| 更正说明 | 来源要求忽略、撤回或指出此前消息有误 |
| 状态未确认 | 措辞不足、否定、疑问或信息不确定；请查看原文 |

`Confirmed for Today` 只表示今天的安排得到确认，不能据此标成已经完成。否定和问句也不能作为完成断言。规则无法理解所有自然语言；遇到未识别或不确定表述时采用保守标签，不调用 LLM 猜测账号到账。

## 两个时间

- **频道发布时间**：Telegram 消息的原始发布时间，编辑后一般不变；它不是 X 原帖发布时间。
- **本次发现时间**：本服务观察到这次有效内容变化的时间；更新消息展示的是新版本被发现的时间。

这两个时间都用北京时间显示，均不等于用户账号实际到账时间。发生网络重试时，群内消息时间可能晚于本次发现时间。

## 哪些编辑会重新提醒

同一个 Telegram 消息 ID，保留完整原始摘要，同时计算有效变更指纹。以下变化通常仍会提醒：

- 从预告变为来源称已完成，或撤回／更正。
- 时间、数字、适用套餐、限制或其他实质正文变化。
- 来源文章或 X 帖子 ID 改变。
- ✅/❌ 等表示资格或状态的符号变化。
- 无法确定只是格式修改的其他编辑。

以下明确等价变化会静默记录，保持原有 sent/pending/dead 状态及退避次数：

- 已审计的预告模板：`Quota Reset Confirmed for Today` 与 `Yet Another Reset Today`；`No specific timeframe announced` 与 `No exact time from Tibo yet`。
- 空白、大小写、已知行首装饰以及重复的 Source/Follow 页脚。
- 同一 X 帖子的常见分享链接变化、来源链接排序，或已知追踪参数变化。

不会整体忽略英文翻译；英文新增时间或适用范围仍是有效变化。不同消息 ID 不做模糊合并，避免把不同重置事件吞掉。

公开 Day 21 消息的三次版本回放结果：首次预告 **1 条**，英文同义改写 **0 条**，新增“14:10 已经重置” **1 条**。

## 旧状态库与回退

升级只给 `posts` 表增加 `semantic_hash` 和 `row_snapshot` 两个带默认值的字段，不清空游标、历史状态或重试次数。旧消息从原摘要及未截断的存量载荷建立比较基线；无法可靠恢复旧正文时保守保留更新提醒。

发布前通过 SQLite backup 接口备份状态库。旧版本忽略新增字段，代码回退不需要删除数据库。再次升级时会核对快照和原始摘要，避免旧版本回写后误用过期快照。不要通过删除 PVC 或全部数据库来消除重复提醒。

被抑制的编辑记录为 `source_edit_suppressed`，不会发到通知群。内容长期不变本身不是故障；采集和投递异常仍由现有日志与健康检查反映。
